# 笔记模板与阅读深度

元数据沿用 schema_version 2：source、稳定 source_id、type、date、tags、wiki_links，并补充 retention、raw_page、evidence。保留 import 生成的来源字段，不能自行替换 ID。

三种保留方式：
- verbatim：提示词、代码、命令、配置，原件逐字保留在 Sources，也完整保留在正文；脚本检查正文包含完整原件。
- procedure：教程、SOP，先列全步骤和前置条件，完整保留操作清单；步骤完整性必须人工核对，脚本不能证明没有漏步骤。
- insight：文章、播客、书、对谈，写观点、依据、限制和判断；不要为凑长度改写全文。

## 正文

1. 摘要：200 字以内，回答这份材料解决什么问题。
2. 核心要点：通常 3–5 条具体断言；短材料按实际内容，不为了凑数虚构。每条保留条件、重要对比项和证据位置。
3. 值得深挖：与已知的连接、批判性视角、思想溯源；有依据才写，没有就写尚未核对。外部资源需用户允许联网后查证。
4. 相关笔记：只连真实存在的页面，写出关联理由。

一个概念只用一个名称；首次出现解释术语；三阶段/四维度等框架首次出现就列全。例子注明属于哪一项；AI 判断的分类标“推断”。引用、代码、原话不为了风格被改写。

## evidence 写法

在 YAML frontmatter 中把空列表替换为：
```yaml
evidence:
  - claim: 你对原文的准确概括
    quote: 原文中能逐字找到的短句
```

quote 不是翻译；英文材料就保留英文原句。脚本能检查字符串存在，却不能证明它支持 claim，也不能证明所有正文结论已穷尽核查。这些仍需阅读判断。

用户观点保持原话和蓝色标注；AI 草稿不使用蓝色。publish 的 review 放元数据作为审阅说明，不伪装成正文的个人沉淀。
