我想要的第二大脑很简单：读过的东西，需要时能找到；留下的结论，能回到原文核对；不同文章里的想法，可以慢慢连起来。

Obsidian 保存和连接笔记，AI 帮我阅读、整理。我负责决定哪些内容值得留下，并核对它说得对不对。

这篇文章最早写于 2026 年 6 月。2026 年 10 月 28 日的这次更新，重新核对了我现行的知识库入口规则、七份任务指南和相关运行脚本，把其中可复用的流程做成公开起步包。**核对的是规则与运行方式，不是把私人库的全部笔记读完或复制出来。**

上一版主要是目录和提示词。这一版补上了真正可运行的来源登记、查重、入库、双链索引、检查与查询。先用一份公开资料跑通，再换成自己的文章。

## 一、准备好，再让 AI 帮你搭

需要 [Obsidian](https://obsidian.md/)、Python 3.11 或以上，以及一个能够访问你指定目录的 AI 工具。你可以使用已配置好的 Claude Code、Codex 等；普通网页聊天无法凭一句提示词直接在电脑上创建文件。模型账号与费用由你自行配置，起步包不附带额度。

最省事的方法：解压 ZIP，在文件型 AI 工具中打开 `stone-second-brain`，把下一节完整提示词发给它。它会检查环境、在独立虚拟环境安装一个固定依赖，并创建一个新的空库。**不要把旧知识库当作初始化目标。**

想自己操作，可以在解压后的工具目录运行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python brain.py doctor
.venv/bin/python brain.py --vault ../我的第二大脑 init
```

以上为 macOS / Linux 命令。Windows 参考包内 `docs/开始使用.md`，尚未实机验收。安装依赖需网络，脚本后续离线运行，不会自行联网调用 AI。

在 Obsidian 选择“打开文件夹为仓库”，选择新建的 `我的第二大脑`，打开 `000-首页.md`。首次首页为空正常；不要把工具目录误当作已经初始化的库。

## 二、给 AI 的完整搭建提示词

这段提示词要求 AI 使用已经测试的脚本，不让它临时编造另一套实现。正式入库前会停下来，让你审阅具体草稿。

```text
请用这个目录里的 stone 第二大脑 v2 起步包，帮我建立可使用的 Obsidian 知识库。不要重新发明脚本。

先读 README.md、CLAUDE.md 和 docs/开始使用.md，确认当前目录有 brain.py 与 requirements.txt。缺文件时停止，不能假装已经安装。如果你不能操作本地文件和终端，明确告诉我并给手动步骤。

先确认要创建的新空库路径；不得改动现有知识库，不复制其他目录的私人笔记、配置或密钥。检查 Python 版本；在本工具目录创建独立虚拟环境，通过 requirements.txt 安装依赖（这一步需网络），不使用 sudo、不改全局环境。运行 brain.py doctor，再用 --vault 指定新目录执行 init。之后脚本均可离线运行。

按开始使用指南，导入包内 Python 官方浮点数教程：保留原链接、语言 en、类型 article、retention insight。读取 import 返回的实际 source_id、raw 和 draft，不猜文件名。完整读 Raw，再按笔记模板在该草稿中写中文摘要、核心要点、值得深挖和 evidence；quote 必须逐字出自原文，区分原文与 AI 推断，不改来源字段。

把草稿、关键引用、限制及建议关联给我看，并停在正式入库前。等我核对并用自己的话复述理解后，才可以用 publish --approve --review；review 使用我本次真实表达，禁止代写授权。没有实际关联就不创建 Wiki，不为凑图谱数量虚构联系。

入库后运行 check、query 主题词、compile 本次 source_id、health。确认首页、索引、队列和双向链接已更新，再重复 import 同一文件，检查没有重复 Note。保持原文和草稿不动。

告诉我如何在 Obsidian 打开新库、从首页点到 Note、Wiki、Raw，打开关系图谱与反向链接。报告实际验证项和未验证项；脚本通过不代表语义自动正确，不声称已经配置模型账号、音视频转录或原库全部插件。

```

规则文件帮助 AI 理解要求，不能保证模型永不犯错。脚本也无法判断一句用户复述是否真诚；你需要真的看过草稿，再让它执行确认后的入库。

## 三、从一份真实资料走完一轮

包内 `examples/python/floatingpoint.rst` 是 [Python 3.13 浮点数教程](https://docs.python.org/3.13/tutorial/floatingpoint.html)的 3.13.0 源文件快照，附原始许可证。它是公开资料，不是虚构的教学原文。即使不懂 Python，也可以把它当成检查“原文有没有保留、引用能不能找回”的练习；正式使用时换成自己熟悉的材料。

从工具目录导入：

```bash
.venv/bin/python brain.py --vault ../我的第二大脑 import examples/python/floatingpoint.rst --title "Python-浮点数与显示误差" --source "https://docs.python.org/3.13/tutorial/floatingpoint.html" --language en --type article --retention insight
```

命令返回实际的 `source_id`、`raw` 与 `draft` 路径。Raw 保留输入字节；草稿出现在 `outputs/drafts/`，里面有待填写项。**导入成功不等于总结已经完成。**

让 AI 完整读取返回的 Raw，按模板补全中文摘要、核心要点、值得深挖和引用证据。草稿里应分清原作者观点、AI 推断及尚不确定的地方。让它展示结果，暂时不要运行 `publish`。

你至少检查三件事：引用能逐字找到；总结没有删掉限制和重要对比；双链有明确关联理由。然后用自己的话复述理解。确认后使用：

```text
.venv/bin/python brain.py --vault ../我的第二大脑 publish outputs/drafts/实际哈希.md --wiki "实际相关概念" --approve --review "我核对后真实写下的理解"
```

替换实际路径与文本；没有相关概念就省略 `--wiki`。AI 不得替你编写审阅确认。脚本会新建正式 Note，在 Wiki 中追加来源索引，更新首页、笔记索引、队列和日志。已有手写定义保留，脚本不会根据一个概念名称自动编造定义。

最后运行：

```bash
.venv/bin/python brain.py --vault ../我的第二大脑 check
.venv/bin/python brain.py --vault ../我的第二大脑 query "浮点数"
.venv/bin/python brain.py --vault ../我的第二大脑 health
```

再在 Obsidian 中从首页打开 Note、Wiki 和 Sources，查看反向链接与关系图谱。`check` 验证文件与链接，`query` 返回关键词匹配的来源位置；它不是能直接回答所有问题的语义搜索。

如果只想先确认环境可用，可以重放包内已核对的固定教学样例：

```bash
.venv/bin/python tests/verify_real_example.py --output ../第二大脑验收示例
```

这会在另一个新目录生成完整示例，使用明确标注的教学审阅记录。它不替你审阅自己的文章，也不能证明任意模型生成的摘要都正确。

## 四、让结果接近我的，靠的是哪些规则

```text
材料 → Sources 原件 → outputs 草稿 → 人工核对
                                      ↓
                                 Notes ↔ Wiki
                                      ↓ 用户真实想法
                                     沉淀
```

**先区分四种内容。** Sources 是证据，Notes 与 Wiki 是整理结果，outputs 是一次性草稿和问答，沉淀是你真实表达的判断。AI 不该把自己的推断写成“我的心得”。

**不同资料采用不同保留方式。** `verbatim` 保留全文，适合转录和需要逐字回看的材料；`procedure` 保留步骤、参数、前置条件与异常，适合操作教程；`insight` 提炼观点，但不删掉关键证据、适用条件和分歧。后两种的完整与准确程度仍需人工判断。

**正式笔记不能只剩一句概括。** 摘要之后写核心要点、值得深挖；第一次出现的术语要解释，框架有几个部分就说明几个部分。教程的步骤不能被“按流程完成”替代。

**Wiki 保留差异。** 多篇材料解释同一个概念时，把各自来源、适用条件和冲突写清楚。不要为了简洁，把有争议的说法变成唯一答案。双链只是连接，不是因果证明。

**区分我和 AI。** 原库用蓝色表示用户原话，AI 整理保持普通文字。公开规则保留这个约定，但颜色本身不能证明作者身份；只有你实际说过的内容才能归为你的判断。没有想法时，沉淀可以为空。

**问答默认只读。** 临时问题不自动变成正式笔记。需要保存时放 `outputs/qa`；是否进入长期知识结构，由你决定。原库的“存、进、沉、跳、查”也在指南里解释，它们是给 AI 的对话约定，不是假装已经安装的系统命令。

## 六、换成自己的资料与日常维护

先选一篇你有权保存的 UTF-8 文本，导入命令中换掉文件路径、标题、来源、语言和保留方式。不要把 PDF、网页快捷方式或音频直接当成正文导入。正文不完整时先补齐，不让 AI 用标题猜内容。

**原始转录要保留。** 音视频需先用其他工具生成并核对转录，再导入文字。人名、否定词、说话人和时间戳尤其需要检查。包内不包含转录引擎，也不自动上传音频。

每次正式入库后运行 `check`。想看哪些内容受某份来源影响，可以运行 `compile` 并传入真实 `source_id`；它只报告影响范围，不自动改写旧笔记。健康检查默认只读，明确使用 `health --write` 才保存报告。

| 遇到的问题 | 处理方式 |
| --- | --- |
| AI 说完成却没有文件 | 检查它是否具有所选目录的写入与终端能力 |
| `init` 拒绝非空目录 | 换一个新空目录，不删除旧库绕过限制 |
| 草稿仍有 TODO 或引用找不到 | 回到原文补齐，不能为了通过检查编造引用 |
| 同一来源内容更新被拒绝 | 保留旧版，决定如何区分新版本；当前不自动合并 |
| `check` 报断链或原件变动 | 找回原文件或从备份恢复，先解决问题再入库 |
| 想在旧库直接使用 | 先备份并审查合并方案；本包不提供自动迁移 |

这个包能复现的是“资料留下来、整理有依据、关联可回查、重复操作不乱写”的工作方式。你的知识数量、关注主题和理解仍要靠自己的阅读积累；下载一个文件夹，不会立刻拥有另一个人的第二大脑。
