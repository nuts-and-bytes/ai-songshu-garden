![双击就能打开自己的窗口，不用先到 Chrome 里找那个标签页。](/images/illustrations/pake-x-desktop.webp)

今天给 Codex 发了 [Pake 的官网链接](https://pake.run/zh#cli)，让它介绍并安装这个工具。

装好以后，我接着说：

> 把我的网页x打包成应用放桌面

它按 X，也就是原来的 Twitter 来处理，开始下载依赖、编译。最后做出了一个约 9.8 MB 的 Mac 应用，桌面上也有了 X 的入口。

双击就能打开自己的窗口，不用先到 Chrome 里找那个标签页。

不过，打开后出现的是 X 的真人验证页面。应用做出来了，也确实能启动，登录和后面的使用还没验证。这两个结果得分开说。

## Pake 做了什么

Pake 可以把网址打包成桌面应用，也支持本地的静态网页。做好的应用有自己的图标和窗口，可以像其他应用一样打开。

里面显示的仍然是网站内容，访问 X 仍然需要联网。它用系统自带的网页引擎显示页面，所以不需要在每个应用里再装一整个浏览器。

这次装的是免费的开源命令行版本 Pake CLI。官网还有带界面的付费桌面版，两个版本要分清楚。命令行版本需要 Node.js、Rust 和相应的编译工具，我这台 Mac 原本就有这些环境。

如果自己在终端操作，打包 X 可以这样写：

```bash
npm install -g pake-cli
pake https://x.com --name X --targets app
```

`--name` 是应用名称，`--targets app` 表示直接生成 Mac 的 `.app`。生成的应用会放在执行命令时所在的目录。其他系统和参数，可以看 Pake 的[官方快速上手](https://pake.run/zh/docs/cli/getting-started)。

## 我只说了要做成什么

我这次没有自己敲上面两行命令，是让 Codex 在电脑上完成的。

先给它工具的官网，让它查清楚怎么安装。装好以后，再说要打包哪个网站、叫什么、放在哪里。下载依赖、执行编译、检查文件和打开应用，都由它接着处理。

最后应用放在用户的“应用程序”目录里，桌面留了一个可双击的入口。

别人想照着试，可以把需求说得比我这次更明确一些：

```text
请按 Pake 官网的说明，检查并安装 Pake CLI。

把 https://x.com 打包成适合我当前电脑的桌面应用，名称叫 X，
并在桌面放一个可以双击打开的入口。

保留已有的同名应用。完成后实际打开检查，告诉我页面能否加载，
以及还有哪些步骤需要我自己完成。
```

这需要在能执行本机命令的 AI 工具里做。我用的是 Codex 桌面端；只在普通聊天窗口里发这段话，AI 没有操作电脑的权限，就没法直接把应用放到桌面。

## 打开以后，还有网站自己的要求

第一次打包需要下载和编译依赖，得等几分钟。不能拿后面重复打包的速度，来估计第一次需要多久。

应用也不会直接沿用 Chrome 里的登录状态，第一次需要重新登录。我这次实际打开 X 时，还遇到了“请验证您是真人”，需要自己完成验证。

Pake 的官方文档也提醒，部分 Google 登录流程会拒绝这种内嵌网页窗口。所以，一个网站能打包成功，不代表它所有的登录方式都能正常用。

目前能确认的是：X 应用已经生成，桌面入口能打开它，也加载出了网站的验证页面。登录后的浏览、通知和长期使用，等真正用过再补。
