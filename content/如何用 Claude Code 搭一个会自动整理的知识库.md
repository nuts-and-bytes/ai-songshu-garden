## 先问：这套东西适合你吗？

在动手之前，先花一分钟判断这套工作流是否真的适合你——**搭错了方向，白费时间**。

**适合这类人：**

- 你每周稳定消化 3 条以上的信息来源（播客、视频、论文、文章），觉得"看了就忘"很可惜
- 你有一个**聚焦的领域**——比如你是研究生在跟踪某个学术方向，或者你在系统学某个行业
- 你希望笔记之间能**互相关联**，而不是一堆孤立的摘录
- 你愿意花半天时间配置，换来之后每次整理只说一句话

**适合这类内容：**

- 播客 / 视频（可以自动转录）
- 学术论文 PDF（适合加文献精读模块）
- 行业文章 / 博客（适合加信息源追踪）

**不太适合：**

- 你只是偶尔做笔记，没有持续输入习惯
- 你的信息来源非常分散，没有一个主题
- 你完全不想碰命令行

> **一句话判断：** 如果你觉得"我消化了很多东西，但三个月后脑子里什么都剩不下"，这套系统就是为你设计的。

---

## 它能做到什么

我只要丢一个播客 / 视频 / 文章链接，说一句 `ingest`，它就**自动**：

1. 下载音频、转录成文字
2. 按我定的模板写一篇结构化笔记（摘要 + 核心要点 + 值得深挖）
3. 识别里面的人物和概念，建成 Wiki 原子卡
4. 用 `[[双链]]` 把它们接进知识图谱
5. 更新目录和操作日志

整个过程我不用动手。攒到现在 70+ 篇笔记、200+ 条链接，没有一篇是我手动整理的。

---

## 三个零件

1. **Obsidian** —— 本地知识库，笔记都存在自己电脑里。
2. **Claudian 插件** —— 让 Claude Code「住进」Obsidian，能直接读写你的文件。
3. **一份 `CLAUDE.md`** —— 给 AI 的说明书，定义它怎么干活。**这是灵魂。**

前两个是工具，真正决定效果的是第三个。

---

## 从零开始：怎么和 Claude Code 对话把它搭出来

这是原文最缺的部分。下面我把完整的对话路径拆成四步，每步给你一个**可以直接复制进 Claude Code 的 prompt**。

> **原则：** 我的架构是一个参考，不是标准答案。下面每个 prompt 里我都标注了「根据你的需求修改」的地方——请认真填，不要照搬我的。

---

### 第一步：设计你的目录结构和笔记模板

先不要急着搭系统，先把**你自己想要什么**想清楚，然后让 Claude Code 帮你设计。

**把这段复制进 Claude Code，填好括号里的内容：**

```
我想用 Obsidian + Claude Code 搭一个个人知识库。

【我的使用场景】
我主要用来整理的内容类型是：[填你的，比如：学术论文/播客/YouTube视频/行业文章]
我的领域或主题是：[填你的，比如：跨文化管理研究/独立游戏开发/个人投资]
我每周大概会 ingest 几条：[填数字]
我希望笔记能支持的查询场景是：[填你的，比如：找某个作者/某个研究方法/某个时间段的内容]

【我的要求】
- 目录结构不超过 5 个顶层文件夹，简单清晰
- 笔记模板适合我上面填的内容类型
- 考虑我以后会用 Dataview 做动态查询

请帮我设计：
1. Obsidian 的目录结构（用树形图展示）
2. 一份笔记 frontmatter 模板（列出所有建议字段和说明）
3. 笔记正文结构（列出各个区块名称和作用）

设计完后，请问我有没有要调整的，不要急着写 CLAUDE.md。
```

Claude Code 会给你出一套方案，**你需要跟它来回确认几轮**，直到你觉得"这就是我想要的"。这一步不要省。

---

### 第二步：生成你的 CLAUDE.md

结构确认好了，再让它写说明书。

**把这段复制进 Claude Code（接着上一步继续对话）：**

```
好，结构我确认了。现在帮我写一份完整的 CLAUDE.md，放在 Obsidian Vault 的根目录。

这份文件是 Claude Code 每次进入这个 Vault 时读取的操作说明书，语气要像给助手写工作手册——直接写规则，不要客气。

必须包含以下章节：

## 目录说明
（每个文件夹是什么，存什么）

## 文件命名规则
（格式：YYYY-MM-DD-{类型}-{slug}.md，举个例子）

## Frontmatter 规范
（列出所有必填字段，说明每个字段的值怎么填）

## 笔记正文结构
（各区块名称和顺序，固定不变）

## ingest 工作流
触发方式：用户输入 `ingest <链接或文件路径>`
步骤：（列出完整流程，包括判断内容类型、提取内容、写笔记、更新 Wiki、更新 index 和 log）

## Wiki 卡规则
（一个实体只能有一个页面，新信息追加不覆盖，文件命名规则）

## 反幻觉铁律
（每条核心要点必须能在原文里找到对应内容，不得根据"大意"发挥）

写好后把完整内容给我，我来决定要不要调整。
```

生成出来的 CLAUDE.md 就是你的系统核心。把它保存到你的 Obsidian Vault 根目录。

---

### 第三步：第一次 ingest 测试

CLAUDE.md 写好之后，用**一条真实内容**做第一次测试。别用你最重要的那条——用一个你已经看过、知道内容的东西，这样你能判断它整理得准不准。

**在 Claude Code 里输入：**

```
ingest [粘贴一个你实际要整理的链接，或者把文章正文粘贴进来]
```

执行完之后，**检查这几件事：**

- 笔记文件有没有按命名规则生成？
- Frontmatter 字段有没有填完整？
- 摘要和核心要点，有没有忠于原文？（最容易出问题的地方）
- Wiki 卡有没有生成，内容对不对？
- index.md 和 log.md 有没有更新？

哪里不对，**直接告诉它**，不要手动改。

---

### 第四步：迭代调教

第一次测试完，几乎一定有要调的地方。**关键：每次反馈都要同时更新 CLAUDE.md**，这样下次就不会再犯同样的问题。

**发现问题时这样说：**

```
刚才生成的笔记有个问题：[描述问题，比如：摘要写得太长了，超过了200字]

以后 ingest 时请改成：[描述你要的，比如：摘要必须控制在150字以内，用一句话说明来源的核心论点]

同时，请更新 CLAUDE.md 里的对应规则，把这条加进去。
```

迭代几次之后，这个系统就会越来越贴合你的使用习惯。我自己大概调了 2 周才觉得顺手。

## 灵魂：CLAUDE.md 怎么写

核心是把你的"规则"写成一份说明书，Claude Code 每次都照着做。我的骨架长这样（**这是我的版本，你的需要根据第一步的对话自己定**）：

```markdown
# 知识库说明书

## 目录结构
- Notes/  每条来源一篇笔记
- Wiki/   概念 / 人物原子卡
- index   目录
- log     操作日志（append-only）

## 文件命名规则
YYYY-MM-DD-{type}-{slug}.md
type 取值：video / podcast / pdf / article

## Frontmatter 必填字段
source: 来源 URL 或文件名
type: 内容类型
date: 处理日期
tags: 必须含 #work 或 #personal 之一
wiki_links: 本篇笔记关联的 Wiki 卡列表

## 笔记正文结构（顺序固定）
1. 摘要（200字内）
2. 核心要点（3-5条）
3. 值得深挖（可选）
4. 相关笔记（可选，用 [[]] 链接）

## 工作流 ingest <链接>
1. 判断类型（视频 / 播客 / 文章）
2. 下载转录
3. 按模板写深度笔记
4. 识别实体 → 新建 / 追加 Wiki 卡
5. 补 [[双链]]，更新 index 和 log

## 铁律
忠于原文：每条核心要点都要能在原文里找到对应的句子，
不许凭"理解了大意"就开始写。
```

> 完整版我还加了「忠于原文」的反幻觉约束、Phase 2 外部资料补充、批量处理队列等。想要我这份完整模板，去小红书找我，评论「AI知识库模板」。

## 门槛（说在前面）

- 需要 **Claude Code**（要订阅），这是核心引擎。
- 转录要配 **yt-dlp + 一个转录 API**（我用 Groq Whisper，有免费额度）。
- 建议先跑通"手动把文字喂给 AI 出笔记"的最小版，再上全自动。

实话说这是进阶玩法，不轻松。但一旦跑通，是真省心。
